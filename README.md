# AI Jira помощник — тестовый прототип

Локальное веб-приложение принимает текст Jira-обращения, переписку и скриншоты. Оно ищет похожие сценарии локально через Ollama, извлекает связанную документацию Confluence и формирует возможные причины, действия и уточняющие вопросы.

В демо-режиме встроено пространство Confluence `WMSDEV` с 20 страницами документации разработки: приёмка, отгрузка, инвентаризация, ТСД и принтеры. Его страницы доступны по адресу `http://localhost:3000/api/demo-confluence`, а наиболее подходящие страницы автоматически добавляются в контекст анализа.

Добавлены пять страниц с примерной логикой кода и точками генерации ошибок: ASN, отгрузка, пересчёт инвентаризации, API ТСД и печать Zebra. Если в обращении указан код ошибки (например, `409 INVENTORY_CELL_NOT_LOCKED`), поиск повышает соответствующую страницу и выводит функцию, условие и место возникновения ошибки.

## Схема агентов

После поиска контекста агент запускает два независимых локальных сабагента через Ollama: первый анализирует текст обращения и похожие сценарии, второй извлекает правила и ограничения из документации. Агент-оркестратор получает только их выводы и строит единый пошаговый сценарий решения. Если один из сабагентов временно недоступен, используется безопасный резервный вывод, который отображается в интерфейсе.

## Запуск

1. Установите Node.js 18 или новее.
2. Скопируйте `.env.example` в `.env`.
3. Для семантического поиска установите [Ollama](https://ollama.com/download), затем один раз выполните `ollama pull embeddinggemma`. Для текстового анализа укажите отдельную чат-модель в `OLLAMA_CHAT_MODEL` (по умолчанию — `qwen3.6:latest`). Для Jira/Confluence добавьте Atlassian-настройки.
4. Дважды щёлкните `start-agent.cmd` (или выполните `node server.js`) и откройте `http://localhost:3000`.

## Настройка интеграций

- **Ollama:** поиск похожих сценариев обращается к локальному `http://localhost:11434/api/embed` с моделью `embeddinggemma`, а текстовый анализ — к `/api/chat` с отдельной чат-моделью `qwen3.6:latest`. Векторы 530 демо-задач кэшируются в памяти приложения и инициализируются одним общим запросом даже при одновременных анализах. `embeddinggemma` нельзя использовать в качестве чат-модели.
- **Jira Cloud и Confluence Cloud:** создайте Atlassian API token в профиле Atlassian и заполните `ATLASSIAN_SITE`, `ATLASSIAN_EMAIL`, `ATLASSIAN_API_TOKEN`. Учётная запись увидит только те проекты и страницы, к которым у неё есть доступ.
- `JIRA_PROJECT` ограничивает поиск задач конкретным проектом. `CONFLUENCE_SPACE` при необходимости ограничивает поиск пространством.
- `JIRA_PROB_PROJECT` задаёт проект с задачами разработки; `JIRA_PROB_JQL` позволяет указать полный JQL-фильтр таких задач. Найденные обращения Jira и задачи разработки показываются в интерфейсе отдельными блоками и помечаются источником.
- При сбое или некорректном JSON от сабагента интерфейс показывает статус `fallback` и текст ошибки. Длина входного текста, изображений и время запросов ограничены настройками из `.env`.

## Проверка без секретов

Приложение содержит 530 обезличенных тестовых заявок: 500 WMS-сценариев и 30 задач разработки типа `Development Bug` с префиксом `PROB`. В 175 WMS-сценариях есть переписка консультанта с пользователем: вопрос, уточняющий ответ и зафиксированное решение. Это включает 100 новых кейсов и 75 кейсов из прежней базы — ровно 50% старых WMS-сценариев. Ещё 250 WMS-кейсов являются переформулированными вариантами предыдущих сценариев. Переписка участвует в локальном семантическом поиске и передаётся сабагенту обращений.

## Ограничения прототипа

- Это помощник для диагностики, не система автоматического исправления: он не меняет Jira, Confluence, права или данные.
- Результаты нужно проверять инженеру перед выполнением действий в продуктивной среде.
- Для корпоративного использования стоит добавить SSO, журналирование, контроль доступа и согласовать передачу скриншотов с политикой безопасности.
